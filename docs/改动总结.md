# 自动填表与邮件投递：改动总结

本分支基于团队的 NextRole 仓库开发；NextRole 的上游为 Roleflow。保留原项目署名、许可证，以及团队已有的申请记录管理功能。本分支名称为 `autofill-and-email`。

## 一、浏览器填表优化

- 文本输入后比较实际保留值与期望值，不再仅检查非空；电话号码允许常见格式符号差异。
- 原生下拉框有同分候选项时拒绝随意选择，选择后检查值是否保留。
- 无候选项的可编辑组合框填写后检查内容是否保留。
- 提交前检查浏览器约束及 `aria-invalid` 错误标记；没有原生表单容器时检查所在文档。
- 核验异常时阻止放行，不将检查失败当作“没有错误”。
- 兼容模型复制的带方括号控件编号，同时仍要求编号存在于当前快照。
- 在失败事件中展示具体停止原因。

这些改动验证的是操作与部分页面状态，不能证明全部字段语义正确，也不能保证所有网站均兼容。

## 二、填表指令调整

- 优先处理带星号、`required` 或 `aria-required` 的字段。
- 必填答案缺失或存在歧义时集中询问用户，不为了填满而猜测。
- 可选项仅在资料有明确依据且有用时填写。
- 不反复改写已完成字段；提交前检查日期、单选组、下拉框和附件。
- 对熟练度等自评题，选项条件缺少依据时询问。

## 三、模型兼容

- 增加 OpenAI 兼容网关的 Chat Completions 路径，支持结构化输出和浏览器图片／工具调用。
- 千问兼容调用显式关闭思考模式；保留上游 Responses 路径。
- 自定义网关暂未接入上游内置联网搜索。
- 只提交通用配置示例，不提交任何真实密钥或个人服务配置。

## 四、新增邮件投递

- 招聘文字和公开网址统一输入文本框。
- 图片、文本型 PDF、DOCX 统一使用一个文件按钮上传。
- 提取公司、岗位、JD、招聘邮箱及邮件格式要求；支持人工更正收件人。
- 根据选定简历附件的内容生成可编辑邮件，避免正文读取另一份全局简历。
- 默认使用 JD 语言，招聘方明确指定语言时优先遵从；正文简洁突出重点，结尾仅保留姓名，不附邮箱或联系方式。
- 草稿保存与发送确认分开；通过 SMTP 发送正文及简历附件。
- 增加邮箱连接和验证界面，本地保存配置，接口不返回授权码。
- 已发送草稿不重复发送；发送结果不确定时阻止自动重发。

## 五、界面与记录层

- 邮件模块嵌入主工作台，顶部增加“邮件投递”入口，保留 `/app/email` 独立页面。
- 复用 `ApplicationRun` 和申请汇总同步，不新增另一套汇总入口。
- `awaiting_approval` 同步为 `saved`，不计入已投递；`submitted` 同步为 `applied`。
- 邮件保存 `messageId` 和发送状态；SMTP 接受发送不等于送达、已读或招聘方受理。
- 保留既有面试／Offer 进度，不因重复同步倒退；同一运行的同一阶段不会重复创建记录。

## 六、测试与交付边界

提交前类型检查、代码检查通过；26 项自动测试通过，1 项独立界面测试跳过。测试涉及文本／下拉核验、提交前检查、邮件生成、邮箱配置脱敏及记录同步；自动测试不发送真实邮件。

本分支不包含实验计时功能、个人运行日志、简历、邮箱配置或授权码。计时记录与分析仅保留本地，不参与团队合并。

- 退信处理、送达／已读确认、全部字段的语义准确性证明。
- 所有平台的登录与访问限制处理；登录、验证码仍需要用户参与。
