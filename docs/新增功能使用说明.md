# 自动填表与邮件投递：新增功能使用说明

## 一、启动

要求 Node.js 20.9+，并安装 Chrome 或 Edge。在 NextRole 项目目录执行：

```bash
npm ci
cp .env.example .env.local
# 编辑 .env.local，填写自己的模型服务配置
npm run dev
```

已有 `.env.local` 时不要覆盖。打开 `http://127.0.0.1:3000/app`；终端保持运行。使用 Edge 时设置 `BROWSER_CHANNEL=msedge`。模型服务地址、密钥和模型名称必须对应；浏览器代理模型需要图片输入和工具调用能力。当前千问兼容请求关闭思考模式，其他服务商需核对参数兼容性。

## 二、浏览器自动填表

1. 上传 PDF/DOCX 简历，核对解析结果，补充所在地、工作许可、签证、薪资和入职时间等资料。
2. 导入真实岗位详情链接；检查职位名称、公司与 JD 是否准确。LinkedIn 来源不代表站内投递，普通申请可能跳转公司网站。
3. 选择本次上传的简历附件，可使用原版或已审核的岗位改写版。
4. 点击 **Run application agent**。首次测试保持自动提交关闭。
5. 登录、验证码或缺失信息出现时，在工作台按提示处理，然后继续。
6. 到最终审核时核对实际页面上的必填项、选项、附件和未知信息。确认后才能批准提交；也可以停止并保留页面。

新增核验会检查部分实际值和页面错误；它不能取代人工判断学历层级、英语等级、薪资单位等语义。资料缺失时应询问，不能为了必填而编造。

## 三、连接发件邮箱

主工作台顶部点击“邮件投递”，定位到内嵌邮件面板。也可直接打开 `/app/email`。展开 **Connect your sending mailbox**。

| 界面项 | 填写内容 |
| --- | --- |
| Provider | 163 Mail 或 Custom SMTP |
| SMTP host | 邮箱服务商提供的发信服务器 |
| Port | 465（TLS）或 587（STARTTLS） |
| Mailbox account | 你的完整发件邮箱账号，不是招聘方邮箱 |
| Authorization / app password | 邮箱授权码／应用专用密码，不一定是网页登录密码 |
| From address | 留空默认使用账号；其他地址须有发信权限 |

点击 **Verify and connect mailbox** 验证并保存。连接成功不发送测试邮件。配置只保存在本机被 Git 忽略的 `data/mail-settings.json`，文件权限仅限所有者，但并非加密；不要分享或提交。当前每次使用一个发件账号，保存的新配置替换旧配置。

也可通过 `.env.local` 的 `SMTP_HOST`、`SMTP_PORT`、`SMTP_USER`、`SMTP_PASS`、`SMTP_FROM` 配置并重启；界面保存的配置优先。

### 各邮箱的理论配置与当前限制

| 邮箱 | 配置与操作 | 当前支持情况 |
| --- | --- | --- |
| 网易 163 | 网页版设置 → POP3/SMTP/IMAP → 开启 SMTP 并获取授权码；`smtp.163.com:465`，使用完整邮箱账号和授权码 | 用户已验收邮件流程 |
| 网易 126 | 同类方式开启 SMTP、生成授权码；Custom SMTP 填 `smtp.126.com:465` | 理论兼容，待实测 |
| QQ 邮箱 | 网页版设置开启第三方 IMAP/SMTP 并生成授权码；Custom SMTP 填 `smtp.qq.com:465` | 理论兼容，待实测 |
| Gmail | 账号开启两步验证；账号允许时生成应用专用密码；`smtp.gmail.com:465` 或 `587` | 应用密码方式理论兼容，待实测；OAuth 尚未实现，普通密码不适用 |
| Outlook.com／Hotmail | 官方要求现代认证 OAuth2；通常通过 `smtp-mail.outlook.com:587` 或 Graph 发信 | 当前未实现 OAuth，不能仅填微软账号密码连接 |
| Microsoft 365／学校邮箱 | 需学校／组织允许第三方应用，使用 OAuth2 SMTP 或 Graph；HKUST 邮箱要求现代认证 | 当前未实现，不要把学校密码填作授权码 |
| 阿里及其他企业邮箱 | 向管理员确认服务器、端口、授权方式；例如阿里邮箱 `smtp.qiye.aliyun.com:465` | 允许账号／应用密码且使用465/587时可尝试；未验收，OAuth／IP限制等需额外适配 |

理论兼容不代表每个账号都可用；以服务商和管理员策略、连接验证及实际收件结果为准。聊天中的邮箱插件不会自动连接到 NextRole。本功能不读取收件箱，也未实现完整邮箱管理。

官方资料：[Gmail 应用密码](https://support.google.com/accounts/answer/185833)、[Gmail SMTP](https://developers.google.com/workspace/gmail/imap/imap-smtp)、[Outlook.com 设置](https://support.microsoft.com/en-gb/outlook/pop-imap-and-smtp-settings-for-outlook-com)、[HKUST 邮箱认证](https://itso.hkust.edu.hk/services/general-it-services/communication-collaboration/email/connect/problem-setting-smtp-server-my-gmail-account)、[阿里邮箱配置](https://help.aliyun.com/zh/document_detail/36576.html)。

## 四、从招聘材料生成邮件

1. 在 **Resume attachment** 选择已上传的简历版本。
2. 在 **Text or recruiting URLs** 粘贴招聘描述、公司／岗位和邮件要求，网址也放在这个框内；最多三个公开网址。
3. 或点击 **Recruiting file** 上传图片、文本型 PDF 或 DOCX，单个文件不超过 8 MB。扫描 PDF 请转为清晰图片；动态加载或登录网页也可使用截图／文字。
4. 如需明确指定招聘方邮箱，在 **Confirmed recipient** 填入；它会覆盖识别邮箱，若不一致会提示核对。
5. 点击 **Extract job and generate email**。系统提取公司、岗位、JD 和招聘邮箱，根据选中的简历生成主题与正文。
6. 核对提取结果、警告、收件人、主题和正文；可以直接编辑。公司、岗位、JD 或有效邮箱缺失时，补充材料再生成。

默认正文简洁、突出岗位匹配点，使用 JD 的语言；招聘方明确指定主题、语言或字数时优先遵从。结尾仅保留姓名，不追加邮箱／联系方式。简历中的邮箱不会自动成为发件账号，实际发件账号由邮箱连接决定。

## 五、保存与发送

1. 点击 **Save draft for review** 保存草稿；此时没有发送。
2. 在下方对应草稿卡片确认正文及简历附件。
3. 邮箱已连接时，点击 **Confirm and send email** 并在确认框中确认。
4. 查看卡片的发送状态、结果说明和邮件 ID；测试时同时在自己的收件邮箱确认收到正文和附件。

若按钮不可用，先检查发件邮箱是否连接或当前是否有操作正在处理。已发送的草稿不会重复发送。发送结果不确定时，不自动重发；先核对邮箱，避免重复申请。

## 六、怎样进入申请记录

浏览器和邮件共用 `ApplicationRun`，不需要新建另一套邮件汇总接口。

| 运行状态 | 申请管理表现 |
| --- | --- |
| `awaiting_approval` | 同步为 `saved`（待投递），不增加已投递数 |
| `submitted` | 同步为 `applied`（已投递） |
| 失败或发送结果不确定 | 不增加已投递数，具体原因看关联运行；既有待投递记录可仍保留 |

邮件的成功标准是 SMTP 服务器接受发送并保存 `messageId`，不代表进入收件箱、已读或招聘方受理。退信处理尚未实现。现有面试／Offer 进度不会因重复同步倒退。

用户打开 `/app/tracking` 查看；开发者沿用 `GET /api/tracking`、`GET /api/tracking/{id}`，必要时用 `POST /api/tracking/sync` 对账。详情返回关联运行，可查看渠道和发送情况。

改动范围见 [改动总结](改动总结.md)，详细接口见 [邮件接口说明](EMAIL_APPLICATIONS.md)。
